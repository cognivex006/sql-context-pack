## 2. Investigate first (report before changing code)

| Item | Required content |
| --- | --- |
| Column type | full length/precision/scale (`nvarchar(50)`, `numeric(38,0)`, `datetime2(7)`, `(max)`) |
| Identity | seed and increment |
| Computed column | definition, persisted |
| Nullability, collation | collation only when different from the database default |
| Primary key | name, clustered/nonclustered, column order ASC/DESC |
| Unique constraints | name, clustered/nonclustered, columns |
| Check constraints | name, definition |
| Defaults | constraint name (including system-generated), definition |
| Foreign keys | name, columns, referenced table/columns, ON DELETE/UPDATE, enabled/trusted (WITH CHECK/NOCHECK) |
| Indexes | name, unique, clustered/nonclustered, key order, INCLUDE columns, filter WHERE |
| Descriptions | `MS_Description` of the table **and every column** (Unicode/Thai preserved) |
| Unsupported features | partition, columnstore, temporal, memory-optimized, sparse: listed, never dropped silently |

## 3. Requirements (only for gaps the investigation confirms)

R1. Lossless metadata: everything in the table above is captured for SQL Server tables.
R2. Neutral output: the DDL file stays standard T-SQL that recreates the object faithfully. Do not add AgriMap section banners, column-group comments, TRY/CATCH wrappers, rerun guards or naming fixes. Keep physical `column_id` order and real constraint names.
R3. Machine-readable metadata: expose the same facts as structured data a consumer can format from (an existing manifest/JSON field or MCP response field; prefer extending an existing structure). Document the schema in the package docs.
R4. Column descriptions are emitted with the DDL (`sp_addextendedproperty` statements) and in the structured data.
R5. Deterministic output: same database → same bytes.
R6. Sensitive-data protection from 3.0.0 is unchanged; metadata is not sample data.
