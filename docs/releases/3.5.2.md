# 3.5.2 — release and migration notes

## Why a patch version

A bug fix with no new surface. The MCP tool surface, CLI, managed header, output format `2` and
the `install.ps1` parameters are unchanged; `-Harness agy` was already accepted and now works.

## What changes

- **Antigravity could not be installed on Windows.** `install.ps1 -Harness agy` called
  `scripts/install-global.ps1 -Mode plugin -Harness agy`. `install-global.ps1` limited `-Harness`
  to `codex`, `claude` and `gemini`, so PowerShell refused the call with a `ValidateSet` error
  before anything was installed. On Windows `sqlctx doctor update --host agy` runs
  `install.ps1 -Update -Harness agy`, and failed the same way.
- `install.ps1` now asks for the skill layout for `agy` and the plugin layout for every other
  host, as `install.sh` already did. Antigravity loads `<skills-root>/<name>/SKILL.md` directly,
  and `global_install.py` refuses the plugin layout for it with `PLUGIN_MODE_UNSUPPORTED`.
- `install-global.ps1` accepts `-Harness agy`. Called directly, it still defaults to
  `-Mode plugin`, so pass `-Mode skill` with `-Harness agy`.

## Not changed

- `scripts/lifecycle.ps1` still accepts only `codex`, `claude` and `gemini`. Its install and
  update leave the Skill to a native plugin manager, which Antigravity does not have. Uninstall
  Antigravity with the manual steps in [the Antigravity guide](../providers/antigravity.md).
- `sqlctx doctor update --host agy` updates an Antigravity install that already exists. Where the
  Skill is not installed yet, `global_install.py update` stops with `NOT_INSTALLED`; use the first
  install command below instead.

## Migration

Update with `sqlctx doctor update --host <host> --version 3.5.2`, then confirm package, plugin
and service versions all report 3.5.2 with `sqlctx doctor check --host <host>`.

For a first Antigravity install, run the installer from the release checkout, then check it:

```powershell
.\install.ps1 -Harness agy
```

```bash
./install.sh --harness agy
```

```bash
sqlctx doctor check --host agy
```

Nothing changes for Codex, Claude Code or Gemini CLI.
