# 3.5.2 — release and migration notes

## Why a patch version

A bug fix with no new product surface. The MCP tool surface, CLI, managed header, output format
`2` and the `install.ps1` parameters are unchanged; `-Harness agy` was already accepted and now
works. The one-line setup below is distribution only: it runs the release's own installers and
adds nothing to the package, CLI or Skill.

## What changes

- **Antigravity could not be installed on Windows.** `install.ps1 -Harness agy` called
  `scripts/install-global.ps1 -Mode plugin -Harness agy`. `install-global.ps1` limited `-Harness`
  to `codex`, `claude` and `gemini`, so PowerShell refused the call with a `ValidateSet` error
  before anything was installed. On Windows `sqlctx doctor update --host agy` runs
  `install.ps1 -Update -Harness agy`, and failed the same way.
- `install.ps1` now asks for the skill layout for `agy` and the plugin layout for every other
  host, as `install.sh` already did. Antigravity loads `<skills-root>/<name>/SKILL.md` directly,
  and `global_install.py` refuses the plugin layout for it with `PLUGIN_MODE_UNSUPPORTED`.
- `install-global.ps1` accepts `-Harness agy`. Called directly, it still defaults to
  `-Mode plugin`, so pass `-Mode skill` with `-Harness agy`.

## One-line setup

Each release now carries four bootstraps and a verified bundle, so a machine installs or updates
with one command, always from the latest release:

```powershell
powershell -ExecutionPolicy Bypass -c "irm https://github.com/cognivex006/sql-context-pack/releases/latest/download/install.ps1 | iex"
powershell -ExecutionPolicy Bypass -c "irm https://github.com/cognivex006/sql-context-pack/releases/latest/download/update.ps1 | iex"
```

```bash
curl --progress-bar -fL https://github.com/cognivex006/sql-context-pack/releases/latest/download/install.sh | sh
curl --progress-bar -fL https://github.com/cognivex006/sql-context-pack/releases/latest/download/update.sh | sh
```

They verify `sql-context-pack-install.zip` against its SHA-256 before unpacking, run the
release's own `install.ps1` or `install.sh` for each host, and report package, plugin and service
versions from `sqlctx doctor check`. A host already registered from another marketplace keeps that
registration and gets only the package and service. `SQLCTX_HOST` picks hosts and
`SQLCTX_DRY_RUN=1` changes nothing. See [Lifecycle](../lifecycle.md#one-line-setup).

## Not changed

- `scripts/lifecycle.ps1` still accepts only `codex`, `claude` and `gemini`. Its install and
  update leave the Skill to a native plugin manager, which Antigravity does not have. Uninstall
  Antigravity with the manual steps in [the Antigravity guide](../providers/antigravity.md).
- `sqlctx doctor update --host agy` updates an Antigravity install that already exists. Where the
  Skill is not installed yet, `global_install.py update` stops with `NOT_INSTALLED`; use the first
  install command below instead.

## Migration

On a machine set up with the one-line installer, run the one-line update. From a checkout, update
with `sqlctx doctor update --host <host> --version 3.5.2`, then confirm package, plugin
and service versions all report 3.5.2 with `sqlctx doctor check --host <host>`.

For a first Antigravity install, run the installer from the release checkout, then check it:

```powershell
.\install.ps1 -Harness agy
```

```bash
./install.sh --harness agy
```

```bash
sqlctx doctor check --host agy
```

Nothing changes for Codex, Claude Code or Gemini CLI.
