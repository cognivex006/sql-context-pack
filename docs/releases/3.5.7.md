# 3.5.7 — release and migration notes

## Why a patch version

Four bug fixes, phase 1b of the [4.0.0 roadmap](../proposals/4.0.0-roadmap.md). The MCP tools,
HTTP routes, CLI commands and options, managed header and output format `2` are unchanged. Two
error codes are new: `UPDATE_RELEASE_UNAVAILABLE` and `UPDATE_RELEASE_UNVERIFIED`.

## What changes

- **`sqlctx doctor check` reports the Claude Code plugin version.** It reads the `id` entries of
  `claude plugin list --json`. For a plugin that loads from a local marketplace folder it reports
  `folderVersion`, the version Claude actually loads.
- **`sqlctx doctor update` works without install provenance.** When no `.sqlctx-install.json`
  exists, as after a host-marketplace install, it downloads the latest release's `update.ps1` or
  `update.sh`, checks it against that release's `SHA256SUMS`, runs it for `--host`, and confirms
  package, plugin and service versions. `--version` pins work only for the latest release on such
  a machine; for any other version it stops with `UPDATE_SOURCE_REQUIRED` and names the latest.
  Use `--source <release-checkout>` to pin an older one.
- **`sqlctx service status` on Windows** reads the SCM service's own token and reports a healthy
  service as `running` with `health_verified: true`.
- **Spatial columns in samples.** On SQL Server, `geometry`, `geography` and `hierarchyid` values
  no longer fail the sample read; each shows as `[BINARY n BYTES]`.

## Verification

Checked on the development machine against the live service and GitHub: `service status` now
reports `running`; doctor reads the Claude plugin version (3.5.6 before this update); the latest
release updater downloads and matches its `SHA256SUMS`. The spatial-sample change is covered by
an automated test; the live check against the test database was skipped because the database
was unreachable from the machine at release time.

## Migration

None. Run `sqlctx doctor update --host <host>`, which now works on every install layout, or the
one-line update, then confirm with `sqlctx doctor check --host <host>`.
