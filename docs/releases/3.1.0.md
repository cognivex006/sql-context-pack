# 3.1.0 — release and migration notes

3.1.0 implements [Requirement v1.2](../spec/design-spec-v1.2.md): SQL Server table exports
carry every property a consumer needs to rebuild or re-format the table, in neutral T-SQL and
in the `table_metadata` YAML.

## Why a minor version

`table_metadata/<schema>__<table>.yaml` gains optional fields (see
[output-format.md](../output-format.md#table-metadata)). Nothing is removed or renamed; the MCP
tool surface, managed header and output format `2` are unchanged.

## What changes on the next export

- SQL Server table `.sql` files change content: full types, identity, defaults, computed
  columns, collation, FK actions, index details and `sp_addextendedproperty` descriptions.
  The `-- Description:` comment line is replaced by `sp_addextendedproperty`.
- Foreign keys are emitted as `ALTER TABLE ... ADD CONSTRAINT` statements after `CREATE TABLE`,
  so `WITH NOCHECK` and disabled keys can be expressed.
- Extracted metadata of SQL Server tables changes once, so the first export after upgrading
  rewrites every table file.
- Other engines are unchanged; their new YAML fields are `null`, `false` or empty.

## Breaking changes

None.

## Known limits

- Index and table storage options (fill factor, padding, data compression, filegroup and
  partition scheme) are listed in `unsupported_features[]` where relevant, not rendered.
- Columnstore, XML, spatial and hash indexes, temporal periods and memory-optimized tables are
  listed, not rendered.
- Round-trip against a live SQL Server was not part of the automated suite for this release;
  the DDL is verified against a fixture and parsed by SQLFluff `tsql`.
