# 3.5.1 — release and migration notes

## Why a patch version

A bug fix with no new surface. The MCP tool surface, CLI, managed header, `DB_METADATA_CONTEXT`
DDL and output format `2` are unchanged.

## What changes

- **False `METADATA_CONTEXT_SCHEMA_DRIFT` on check constraints.** SQL Server does not keep a
  check constraint as written. `[OBJECT_TYPE] IN ('TABLE', 'PROCEDURE', 'FUNCTION')` is stored as
  `([OBJECT_TYPE]='FUNCTION' OR [OBJECT_TYPE]='PROCEDURE' OR [OBJECT_TYPE]='TABLE')`,
  `LEN(x) BETWEEN 1 AND 64` as `len(x)>=(1) AND len(x)<=(64)`, and `x NOT LIKE p` as
  `NOT (x) like p`. 3.5.0 compared the stored text with the packaged text and reported
  `CK_DB_METADATA_CONTEXT_CLASSIFICATION`, `_CONTEXT_CODE`, `_OBJECT_TYPE`, `_SOURCE` and
  `_STATUS` as drift on a correctly built table, so inventory sync and context index reads
  were refused.
- The check now parses each definition into a canonical expression tree and compares trees.
  Semantic changes are still drift, including regrouping that the 3.5.0 text comparison missed.
  A constraint that is disabled, not trusted or marked `NOT FOR REPLICATION` is still drift.

Default constraints and filtered index definitions keep the 3.5.0 comparison; they were not
affected.

## Migration

Update with `sqlctx doctor update --host <host> --version 3.5.1`, then confirm package, plugin
and service versions all report 3.5.1 with `sqlctx doctor check --host <host>`.

Do **not** re-apply or alter `DB_METADATA_CONTEXT` because 3.5.0 reported check drift. A table
built from the packaged DDL already matches. After updating, retry the inventory sync. If it
still reports drift, the details name the constraints to compare against
`sql/DB_METADATA_CONTEXT/table/DB_METADATA_CONTEXT.sql`; include `is_not_for_replication`
when reading `sys.check_constraints`.
