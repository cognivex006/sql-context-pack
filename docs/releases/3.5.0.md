# 3.5.0 — release and migration notes

Requirement [v1.7](../spec/design-spec-v1.7.md).

## Why a minor version

New, backward-compatible surface: the `filtered` selection mode, the `filtered_scope` inclusion
reason, the optional `unmatched_wildcard_patterns` catalog status field, and two finding codes.
Output format `2` and the managed header are unchanged.

## What changes

- **Filtered object scope.** Name an object set (`V2_*`, `LM_*`, `SYSTEM_CONFIG`) and the agent
  creates an include-pattern catalog with `selection.mode=filtered`, exports every match, and
  runs fetch/assemble/validate itself when you named a destination inside the workspace.
- **Fail early, not after export.** Selecting `all` on an include-pattern catalog is rejected at
  selection time with `ALL_MODE_INCLUDE_FILTER_CONFLICT`.
- **Patterns.** Include and exclude ignore letter case. A wildcard that matches nothing is
  reported in `unmatched_wildcard_patterns`; an exact name that matches nothing still stops.
- **Fewer refusals.** Non-security limits are reported with counts while the run continues.

## Fixed

- SQL Server `sqlctx_list_context_index` and `sqlctx_sync_context_index` no longer fail with
  `DATABASE_OPERATION_FAILED` / `decimal.ConversionSyntax` while checking the metadata table.
  The identity seed and increment (`sql_variant`) are read as text.
- Skill: actor ID from an all-digit owner ID, asked once; every visible blocker checked before
  asking the owner for anything.

## Security

- Windows master keys under the service runtime are protected with machine-scope DPAPI. A copied
  runtime folder no longer decrypts on another machine.
- The service no longer serves `/api/docs`, `/api/openapi.json` or ReDoc without a bearer.
- `doctor update` reports `UPDATE_SIGNATURE_UNVERIFIED` when the release tag has no verifiable
  signature. Releases are not signed yet, so this is informational.
- Still open: hash-pinned dependency installation and enforced tag signatures.

## Breaking changes

None in the documented contract. Anything that fetched `/api/docs` or `/api/openapi.json` from a
running service must read `docs/generated/openapi.json` instead.

## Migration

Follow [docs/knowledge/upgrade-to-3.5.0.md](../knowledge/upgrade-to-3.5.0.md). In short: upgrade
the package, repair the service from an Administrator PowerShell, update the host plugin, open a
new host session, connect a profile once so master keys convert, then confirm all three versions
with `sqlctx doctor check --host <host>`. No profile or credential is recreated.

Machines on 3.3.0 or older cannot use `doctor update` for this hop: their trust check expects the
repository's former name. The guide gives the one-time install path.
