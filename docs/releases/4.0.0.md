# 4.0.0 — release and migration notes

## Why a major version

30 MCP tools are removed. That changes the agent-facing contract, so it is a major version under
AGENTS.md §3. Nothing else breaks: every HTTP route, every owner CLI command, the managed header and
output format `2` are unchanged, and files written by any 2.x or 3.x release keep working.
Requirement [v2.0](../spec/design-spec-v2.0.md); phase 3 of the
[4.0.0 roadmap](../proposals/4.0.0-roadmap.md).

## The eight core tools

| Tool | Use |
|---|---|
| `sqlctx_get_status` | What can I use: capabilities, profiles, folder IDs, SQLFluff readiness |
| `sqlctx_test_profile` | Connection test (the bridge's `connect` and `change` use it) |
| `sqlctx_pull` | Export context into a registered folder as one job |
| `sqlctx_wait_pull` | Wait on a pull; `timeout_seconds=0` reads its status at once |
| `sqlctx_query_data` | Protected, read-only SELECT |
| `sqlctx_list_context_index` | Read the context index |
| `sqlctx_plan_routine_deployment` | Plan a routine update |
| `sqlctx_apply_routine_deployment` | Apply it, approval-bound |

The four bridge session tools and the two export resources are unchanged.

## Replacements for removed tools

| Removed MCP tool | Use instead |
|---|---|
| `sqlctx_get_capabilities`, `sqlctx_list_profiles`, `sqlctx_list_managed_folders`, `sqlctx_sqlfluff_status` | `sqlctx_get_status` |
| `sqlctx_create_catalog`, `sqlctx_list_catalogs`, `sqlctx_get_catalog_status`, `sqlctx_cancel_catalog`, `sqlctx_get_category_preview`, `sqlctx_set_materialization_selection`, `sqlctx_list_sitemap`, `sqlctx_get_materialization_plan`, `sqlctx_get_classification_requests`, `sqlctx_submit_classification_proposals` | `sqlctx_pull` (+ `sqlctx_wait_pull`); per-object failures are in the pull status |
| `sqlctx_export_batch`, `sqlctx_list_exports`, `sqlctx_get_export_status`, `sqlctx_cancel_export`, `sqlctx_validate_exports` | `sqlctx_pull`, which exports, assembles and validates |
| `sqlctx_get_pull_status` | `sqlctx_wait_pull` with `timeout_seconds=0` |
| `sqlctx_resolve_classifications`, `sqlctx_resolve_context_index`, `sqlctx_sync_context_index` (owner mode) | `sqlctx context-index resolve` then `sqlctx context-index sync-plan` (owner CLI); the pull's inventory sync covers the unattended case |
| `sqlctx_plan_context_generation` | `sqlctx context-index generate-plan` |
| `sqlctx_plan_folder_classification`, `sqlctx_apply_folder_classification` | `sqlctx folder plan` / `sqlctx folder apply` |
| `sqlctx_sqlfluff_ensure`, `sqlctx_sqlfluff_update` | `sqlctx sqlfluff ensure` / `sqlctx sqlfluff update --version <x.y.z>` |
| `sqlctx_delete_catalog`, `sqlctx_delete_export` | Retained jobs expire on their own; `sqlctx runtime cleanup-expired` removes expired ones |

## Verification

- Automated: `scripts/dev-check.ps1` passes, including the end-to-end pull through the real
  facade, SQLFluff, export and assembly with only the database connection simulated, and contract
  tests that pin the exact eight-tool surface and keep every surviving v1.21 tool contract
  byte-identical.
- Not yet done: the live pull against the SQL Server test database (requirement v1.9 item 8),
  because the database was unreachable from the release machine.

## Migration

1. Update with `sqlctx doctor update --host <host>` and confirm package, plugin and service with
   `sqlctx doctor check --host <host>`.
2. Open a new host session so the Skill and bridge load the new surface. An old session still
   lists removed tools until it is reopened; calls to them fail as unknown tools.
3. Scripts or prompts that called a removed tool: use the table above.
