# 3.4.0 — release and migration notes

Requirement [v1.6](../spec/design-spec-v1.6.md).

## Why a minor version

New, backward-compatible surface: the `sqlctx doctor fix` action, its `--finding` option, new
service finding codes and optional fields on service findings. The MCP tool surface, managed
header and output format `2` are unchanged.

## What changes

- **Doctor names the service fault.** The health probe is classified instead of collapsing into
  `SERVICE_UNAVAILABLE`: `SERVICE_DOWN`, `SERVICE_HUNG`, `SERVICE_AUTH_REJECTED`,
  `SERVICE_METADATA_INVALID`, `SERVICE_UNHEALTHY` and `PORT_OWNER_MISMATCH`.
  `SERVICE_UNAVAILABLE` remains only for faults none of these explain.
- **Every service finding proposes a fix.** Findings carry `diagnosis`, `evidence` (port,
  listener PID and start time, SCM service PID and state, `CLOSE_WAIT` socket count) and
  `proposed_fix` (`fix_id`, `command`, `requires_elevation`, `effect`). Evidence never holds URLs,
  tokens, metadata, database hosts or SQL.
- **`sqlctx doctor fix --host <host> [--finding <CODE>]`** applies the proposed fix and verifies
  it by re-inspecting. It stops with `DOCTOR_FIX_NEEDS_ELEVATION` and the exact Administrator
  command when it lacks the rights, and refuses to stop any process that is not the SQL Context
  Pack service.
- **SCM service alive without its server.** When Windows reports the service `RUNNING` but
  nothing listens, doctor says so and proposes a restart, since a plain start is refused.
- The health probe timeout is 5 seconds (was 3).

## Security

Dependencies were checked against OSV (api.osv.dev) on 2026-10-29. Pins with advisories are
raised to versions that fix them:

- `certifi` floor `>=2026.10.23` (transitive via httpx) — GHSA-6q48-6c7w-9gw2 / PYSEC-2026-4320, critical:
  bundled emSign roots with compromised intermediate keys.
- `cryptography` 49.0.0 → 50.0.2 — GHSA-g6cj-pr64-35w5, high: PKCS#7 Bleichenbacher oracle.
- `dnspython` floor `>=2.9.0` (transitive via email-validator) — GHSA-45c3-73f7-pv4m, high.
- `mcp` 1.28.1 → 1.30.0 — four moderate advisories (cross-origin redirect header leak,
  unbounded StreamableHTTP sessions, server-chosen `$ref` fetch, bearer audience check).
- Build: `setuptools` 83.0.0 → 84.2.1 (GHSA-xmj3-9gf7-h52w, low); `packaging` 25.0 → 26.3
  (no advisory; aligns with current tooling so `dev-check` builds).
- Known, unfixed: optional `mariadb` 1.1.14 extra has PYSEC-2026-217 and no fixed release. It is
  not installed by default; prefer the `mysql` extra (PyMySQL) for MariaDB servers until a fix ships.

## Breaking changes

None. Consumers matching on `SERVICE_UNAVAILABLE` should also accept the new codes; each still
carries `action`.

## Migration

`sqlctx doctor update --host <host>`, then open a new host session to load the updated Skill.
