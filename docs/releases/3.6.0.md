# 3.6.0 — release and migration notes

## Why a minor version

It adds three MCP tools and three HTTP operations and removes nothing: every earlier tool, route,
CLI command, the managed header and output format `2` are unchanged. Requirement
[v1.9](../spec/design-spec-v1.9.md); phase 2 of the [4.0.0 roadmap](../proposals/4.0.0-roadmap.md).

## What changes

Ask for context in a folder once:

1. The agent calls `sqlctx_pull` with a registered folder ID (and name patterns, if you named
   objects). If anything would stop the job (an unregistered folder, SQLFluff not ready, a schema
   outside the profile, a database that does not answer), the reply is `blocked` with every
   problem and the exact command that fixes it. Nothing has started.
2. Otherwise the service runs the whole pipeline as one job while the agent calls
   `sqlctx_wait_pull`, each call returning within 50 seconds.
3. The final status carries one set of counts and every warning. Files are written under the
   folder's output root; unmanaged files are never overwritten and stale managed files are kept
   and counted, never deleted.

The context index sync runs when the agent passes your numeric ID as `actor_id` and the profile
allows `metadata_context_write` on SQL Server; otherwise it is skipped with a warning that names
the remedy.

## Before you use it

Register the destination once from your own terminal; the agent only ever sees the opaque ID:

```bash
sqlctx folder register --input-root <sql-input-folder> --output-root <context-output-folder> --engine sqlserver
```

## Migration

None. Update with `sqlctx doctor update --host <host>`, confirm with
`sqlctx doctor check --host <host>`, and open a new host session so the Skill and bridge load
the new tools.
