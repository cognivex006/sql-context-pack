# 3.3.1 — release and migration notes

## Why a patch version

A bug fix with no new surface. The MCP tool surface, CLI, managed header and output format `2`
are unchanged. `DATABASE_OPERATION_FAILED` gains optional detail fields (`statement`,
`sql_error_numbers`, `correlation_id`).

## What changes

- **SQL Server table catalogs on non-Latin1 databases.** From 3.1.0, every table failed analysis
  with `DATABASE_OPERATION_FAILED` when the database collation was not Latin1 (for example
  `Thai_CI_AS`). The table-features query concatenated catalog names with
  `data_compression_desc` (`Latin1_General_CI_AS_KS_WS`), and SQL Server rejected it with
  errors 451 and 8180. Every feature detail is now collated to `DATABASE_DEFAULT`.
- **Version-gated optional probes.** Temporal (SQL Server 2016+) and memory-optimized (2014+)
  probes run only where supported. If one still cannot run, the table records
  `probe_unavailable` in `unsupported_features` and its analysis does not fail.
- **Diagnosable metadata failures.** The error names the failed statement and the SQL Server
  error numbers. A protected diagnostic under `runtime_root/errors` holds SQLSTATE and the
  bounded driver message. It never holds credentials, SQL or data.

## Repository migration — 2026-10-20

Version 3.3.1 is republished from https://github.com/cognivex006/sql-context-pack.
Its new repository tag includes the removal of GitHub Actions workflows and updated canonical
install/update URLs. GitHub Actions are disabled on the new repository; verification runs locally.
There are no MCP, CLI or output-format changes in this migration.

Checkouts from the previous repository must change `origin` to
`https://github.com/cognivex006/sql-context-pack.git` and use the new main checkout before
running a source-based update. Existing installed updaters that still reference the previous
repository need an owner-run update from the new checkout using the
[documented installer for their host](../getting-started.md).

## Migration

Update with `sqlctx doctor update --host <host> --version 3.3.1`. Re-run any catalog that
failed under 3.1.0–3.3.0. Retained exports need no change.
