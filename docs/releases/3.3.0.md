# 3.3.0 — release and migration notes

3.3.0 implements [Requirement v1.4](../spec/design-spec-v1.4.md): formatting fitted to each of
the five dialects.

## Why a minor version

`sqlctx format` gains the optional `--profile` option. Nothing is removed or renamed; the MCP
tool surface, managed header and output format `2` are unchanged.

## What changes

- **Dialect selection.** `--dialect` when given; otherwise the engine of `--profile <name>`
  (read from the profile definition, no credential or connection); otherwise `tsql`. Before,
  the default was `ansi`.
- **Excluded rules per dialect.** Every dialect excludes `CP02` (identifier recasing), `CV02`
  (`NVL`/`IFNULL`/`ISNULL` to `COALESCE`) and `RF06` (identifier unquoting). `tsql`, `oracle`
  and `ansi` also exclude `LT01`; PostgreSQL, MySQL and MariaDB now get its spacing fixes.
- **Cache and fingerprint.** The rule policy is part of the format cache key and tooling
  fingerprint, so nothing formatted under the old rules is reused.

## Breaking changes

None to a contract. Behaviour changes to plan for:

- Formatted output keeps `ISNULL`, `IFNULL` and `NVL` instead of rewriting them to `COALESCE`.
  Re-exported files differ from 3.2.x exports where those functions appear.
- PostgreSQL, MySQL and MariaDB output gains spacing fixes (for example `a=1` becomes `a = 1`).
- `sqlctx format` without `--dialect` formats as `tsql`, not `ansi`. Pass `--dialect ansi` for
  the old behaviour.

## Migration

1. Update to 3.3.0 (`sqlctx doctor update --host <host>`).
2. Re-export if you want existing files to use the new rule sets; tooling fingerprints change,
   so the next export reformats.

## Bounds

- SQLFluff 4.2.2 cannot lex Oracle alternative quoting (`q'[...]'`); that SQL ends
  `parse_failed` and is preserved unchanged.
- The round-trip proof uses one realistic sample per dialect, not every construct of each
  dialect.
