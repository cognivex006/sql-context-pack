# 3.2.1 — release and migration notes

A patch release fixing how Oracle object definitions are read.

## Why a patch version

A bug fix only. No MCP tool, CLI option, profile field, managed header or output format change.

## What changes

- **Oracle definitions.** `DBMS_METADATA.GET_DDL` was called with `:2, :1` while the adapter
  passed `(schema, name)`. python-oracledb binds by position, left to right, and pays no
  attention to the placeholder number, so GET_DDL received the schema as the object name.
  Tables then fell back to a column-only `CREATE TABLE`, and procedures and functions failed
  with `DEFINITION_UNAVAILABLE` (or returned a different object where a schema and an object
  shared the swapped names). The queries now bind `:1` (schema) and `:2` (name) in order and
  call `GET_DDL('<TYPE>', name, schema)`.

## Breaking changes

None.

## Migration

1. Update to 3.2.1 (`sqlctx doctor update --host <host>`).
2. Re-export Oracle tables, procedures and functions exported with 3.2.0 or earlier; their
   definitions were incomplete or unavailable.

## Bounds

Verified by a contract test that applies python-oracledb's documented binding rule, not
against a live Oracle database.
