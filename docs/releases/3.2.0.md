# 3.2.0 — release and migration notes

3.2.0 implements [Requirement v1.3](../spec/design-spec-v1.3.md): security hardening across all
five engines.

## Why a minor version

Oracle profiles gain an optional `oracle_connect_mode` field. Nothing is removed or renamed; the
MCP tool surface, managed header and output format `2` are unchanged.

## What changes

- **SQL Server connection strings** brace every value. A password containing `;`, `=` or `}`
  that used to fail login now works, and cannot inject `Encrypt` or `TrustServerCertificate`.
- **Query Data on PostgreSQL, MySQL, MariaDB and Oracle** first proves the login is read-only,
  as SQL Server already did. See the checks in the requirement.
- **Locking reads** (`FOR UPDATE`, `FOR NO KEY UPDATE`, `FOR SHARE`, `FOR KEY SHARE`,
  `LOCK IN SHARE MODE`) are refused by the validator.
- **Format diagnostics** redact quoted literals and secret assignments, keep rule codes and
  line/position, state truncation, and add `diagnostic fingerprint: <12 hex>`.
- **Oracle** DSNs are built with `oracledb.makedsn` from `oracle_connect_mode`
  (`service_name` default, `sid`, `tns_alias`). `sqlctx configure` asks for it.

## Breaking changes

None to a contract. One behaviour change to plan for:

- A PostgreSQL, MySQL, MariaDB or Oracle profile whose login holds write, DDL, EXECUTE or admin
  capability, or (MySQL/MariaDB) any granted role, is now refused by `sqlctx_query_data` with
  `QUERY_READ_ONLY_CONTEXT_REQUIRED`. Export and catalog are unaffected. Fix: point the profile
  at a SELECT-only login.

## Migration

1. Existing Oracle profiles need no change: no `oracle_connect_mode` means `service_name`, the
   previous `host:port/service` behaviour. A profile that relied on a SID or a TNS alias in the
   database field should set `oracle_connect_mode: sid` or `tns_alias` (re-run
   `sqlctx configure`, or edit `profiles.yaml`).
2. Check each non-SQL-Server Query Data login is SELECT-only.

## Known limits

- The read-only checks were verified against recorded catalog answers in the automated suite,
  not against live PostgreSQL, MySQL, MariaDB or Oracle servers.
- MySQL/MariaDB role privileges are not expanded; any granted role is refused instead.
- Diagnostics redaction covers quoted literals and `name=value` secrets; an unquoted literal
  (for example a bare number) is not redacted.
