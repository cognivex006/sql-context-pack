# 3.5.6 — release and migration notes

## Why a patch version

It fixes formatting that was silently skipped and adds no surface. The MCP tools, HTTP routes,
CLI, managed header and output format `2` are unchanged.

## What changes

- **Most objects are now actually formatted.** SQLFluff exits 1 whenever a violation it cannot
  fix remains, even after it has formatted the file. Until 3.5.5 that exit code made the
  formatter discard SQLFluff's output and keep the unformatted text, reported as
  `format_failed`. Now the formatted file is kept when remaining unfixable lint is the only
  cause, it still parses, and its managed header is intact. Its diagnostics say
  `unfixable_lint_violations_remaining: <count>`.
- **Real failures are unchanged.** Parse and templating errors, other exit codes, and output
  that no longer parses still keep the original text.

## What you will see

On the 1,032-object test export, `formatted` goes from 71 to 995 and `format_failed` from 924
to 0; `parse_failed` stays at 37. Export warnings drop with it, because each remaining-lint
object carries one short diagnostic instead of SQLFluff's full report.

The formatted body of those objects differs from 3.5.5, so their `content_hash` and the
bundle hash change. Assembling into a folder written by 3.5.5 replaces those managed files as
ordinary content updates. Results cached as failed by 3.5.5 are not reused; the first export
after the update formats them again.

## Migration

None. Run the one-line update, or `sqlctx doctor update --host <host> --version 3.5.6` where
install provenance exists, then confirm package, plugin and service versions with
`sqlctx doctor check --host <host>`.
