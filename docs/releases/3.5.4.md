# 3.5.4 — release and migration notes

## Why a patch version

It fixes a stall and adds no surface. The MCP tools, HTTP routes, CLI, managed header, output
format `2` and every response field are unchanged.

## What changes

- **Metadata reads time out.** Catalog, sample and dependency reads now stop after 120 seconds
  where the driver supports a statement timeout, as Query Data already did. On SQL Server this
  covers every read. A timed-out object is reported in `failures[]` with
  `DATABASE_OPERATION_FAILED` and the catalog continues with the remaining objects.
- **No double wait.** A read that timed out is not retried. A reused connection that fails for
  any other reason is still retried once on a fresh connection, as in 3.5.3.

## What you may see

An object that used to hang a catalog now appears as one analysis failure. Its diagnostic,
under the service runtime `errors/` folder, names the timeout. Running the catalog again later
picks the object up once whatever held the lock has finished; the other objects reuse their
checkpoints.

PostgreSQL, MySQL, MariaDB and Oracle drivers used here expose no per-cursor timeout, so their
behaviour is unchanged; MySQL keeps its 30-second read timeout.

## Migration

None. Update with `sqlctx doctor update --host <host> --version 3.5.4`, or the one-line update,
then confirm package, plugin and service versions all report 3.5.4 with
`sqlctx doctor check --host <host>`.
